# Skill: User Story Format

## Formato estándar

```
Como [rol específico],
quiero [acción concreta],
para [beneficio claro].
```

## Buenos ejemplos

✅ "Como agencia que usa Minuta, quiero exportar las minutas a PDF para enviarlas al cliente externo."

✅ "Como editor de proyecto, quiero etiquetar minutas por cliente para encontrarlas rápido después."

## Malos ejemplos

❌ "Como usuario, quiero usar el sistema para hacer cosas." (genérico)

❌ "Como Esteban, quiero el botón rojo para que me guste." (decisión técnica disfrazada de story)

## Criterios de aceptación por story

Cada user story tiene criterios de aceptación bajo el formato:

```
DADO [contexto]
CUANDO [acción]
ENTONCES [resultado]
```

## INVEST (test de calidad de la story)
- **I**ndependent — no depende de otra story para tener valor.
- **N**egotiable — el detalle se puede ajustar.
- **V**aluable — entrega valor al usuario o negocio.
- **E**stimable — el equipo puede estimarla.
- **S**mall — entra en un sprint.
- **T**estable — se puede verificar si funciona.
