# Skill: Discovery Framework

## Propósito
Estructura del discovery de un proyecto de producto digital.

## Estructura

### 1. Contexto del cliente
- Industria, tamaño, cultura.
- Stack tecnológico actual.
- Equipos disponibles.

### 2. Problema a resolver
- ¿Quién tiene el problema?
- ¿Cómo lo resuelve hoy?
- ¿Cuánto le cuesta hoy?
- ¿Cuánto vale resolverlo?

### 3. Usuarios
- Personas principales.
- Jobs to be done.
- Pain points.
- Goals.

### 4. Producto existente (si hay)
- Funcionalidades actuales.
- Limitaciones.
- Métricas de uso.

### 5. Modelo de negocio
- Cómo monetiza el cliente.
- Cómo el producto encaja en el negocio.
- KPIs de éxito.

### 6. Restricciones
- Presupuesto.
- Plazos.
- Stack tecnológico.
- Compliance legal.

### 7. Riesgos identificados
- Riesgos de producto.
- Riesgos técnicos.
- Riesgos comerciales.

### 8. Hipótesis iniciales
- Qué creemos que funcionará.
- Cómo lo vamos a validar.

## Reglas
- NO saltarse el discovery.
- SÍ marcar inferencias.
