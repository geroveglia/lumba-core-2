# Workflow 03.5: Bootstrap Scaffolding (Tipo A — Greenfield)

> **Se ejecuta SOLO para proyectos Tipo A, inmediatamente después de que Gero aprueba el ADR del Tech Stack.**
> **Inicializa la estructura de carpetas, documentación base y configuración del proyecto automáticamente.**

---

## Principio

> **El equipo de desarrollo no debería perder tiempo en setup inicial.**
>
> Después de decidir el stack, el proyecto debería estar listo para codear en minutos, no en horas.

---

## Cuándo se usa

- **Exclusivamente en proyectos Tipo A (Greenfield).**
- Inmediatamente después de que Gero aprueba el ADR de Tech Stack (Workflow 03).
- Una sola vez al inicio del proyecto.

---

## Qué hace

### 1. Crear estructura de carpetas

```
proyectos/{nombre}/
├── README.md                          ← del template, adaptado al proyecto
├── MEMORIA-PROYECTO.md                ← ya instanciado en Workflow 00
├── state.json                         ← ya existe
├── outputs/                           ← ya existe
├── approvals/                         ← ya existe
├── docs/
│   ├── decisions/                     ← ADRs
│   │   ├── ADR-000.md                 ← ya existe (Project Assessment)
│   │   ├── ADR-001.md                 ← Tech Stack Decision
│   │   └── ADR-002.md                 ← Database Design Decision
│   ├── arquitectura.md
│   ├── api.md
│   ├── modelo-datos.md
│   ├── entornos.md
│   └── deploy.md
├── src/
│   ├── components/
│   ├── pages/
│   ├── hooks/
│   ├── services/
│   ├── styles/
│   ├── types/
│   └── utils/
├── db/
│   └── migrations/                    ← SQL migrations del Data Architect
├── tests/
│   ├── unit/
│   └── e2e/
├── .env.example                       ← variables de entorno (nombres, no valores)
├── .gitignore                         ← basado en el stack elegido
├── .editorconfig
├── .prettierrc.json                   ← del stack-a-config
├── eslint.config.js                   ← del stack-a-config (si Stack A)
└── tsconfig.json                      ← del stack-a-config (si Stack A)
```

### 2. Inicializar archivos de configuración

| Archivo | Fuente | Stack A | Stack B | Stack C |
|---|---|---|---|---|
| `.editorconfig` | `shared/infra/stack-a-config/` | ✅ | ✅ | ✅ |
| `.prettierrc.json` | `shared/infra/stack-a-config/` | ✅ | ✅ | ✅ |
| `eslint.config.js` | `shared/infra/stack-a-config/` | ✅ | Adaptar | Adaptar |
| `tsconfig.json` | `shared/infra/stack-a-config/` | ✅ | Adaptar | Adaptar |
| `.gitignore` | Generado según stack | ✅ | ✅ | ✅ |
| `.env.example` | Generado del ADR | ✅ | ✅ | ✅ |

### 3. Inicializar package.json

```json
{
  "name": "{proyecto}",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev": "...",
    "build": "...",
    "test": "...",
    "lint": "..."
  },
  "dependencies": {
    // según stack elegido
  },
  "devDependencies": {
    // según stack elegido
  }
}
```

### 4. Inyectar documentación base

- `docs/arquitectura.md` — stack, decisiones, diagrama conceptual
- `docs/entornos.md` — dev/staging/prod, URLs, cómo deployar
- `docs/deploy.md` — pasos de deploy, rollback, troubleshooting
- `README.md` — adaptado del `project-memory-template` con setup instructions

---

## Pasos

```
1. PM Agent → lee ADR de Tech Stack (ADR-001)
2. PM Agent → lee project-memory-template.md
3. PM Agent → genera estructura de carpetas
4. PM Agent → copia archivos de configuración desde shared/infra/
5. PM Agent → genera package.json según stack elegido
6. PM Agent → genera documentación base
7. PM Agent → actualiza MEMORIA-PROYECTO.md con la estructura creada
8. Jarvis notifica a Gero:
   "⚡ {proyecto}: Bootstrap completo. Stack {A/B/C}.
    Estructura lista en /proyectos/{nombre}/
    Arrancamos a codear cuando digas."
```

---

## Outputs

- Estructura de carpetas completa
- Archivos de configuración del stack
- `package.json` con dependencias iniciales
- Documentación base (arquitectura, entornos, deploy)
- `README.md` del proyecto

---

## Quality Gate

- **Bootstrap Gate** — la estructura debe coincidir con el stack elegido en el ADR.
- Si falta algún archivo de configuración → no se avanza a Build.

---

## Duración estimada

30 minutos (todo automatizado por el agente).

---

## Validación humana

- Gero revisa la estructura antes de arrancar el desarrollo.
- Si quiere ajustar algo (ej. agregar carpetas específicas), lo pide y se re-ejecuta.

---

## Anti-patterns

- ❌ "La estructura la armamos sobre la marcha."
- ❌ "Cada dev crea sus propias carpetas."
- ❌ "No necesitamos .editorconfig, es una boludez."
- ❌ "El package.json lo genera el CLI del framework."
