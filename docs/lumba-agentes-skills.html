📐 Fórmula de Cálculo de Costo

Costo Total = Σ ( invocaciones × costo por tarea ) para cada agente

Donde:
  costo por tarea = tokens_input × precio_input + tokens_output × precio_output
  invocaciones = depende del tipo de proyecto (40-800 tareas)

Ejemplo (Proyecto Complejo como Looped):
  12 agentes × 40-60 tareas c/u = ~500 tareas
  70% Flash (~$0.03/tarea) + 25% Pro (~$0.15/tarea) + 5% Opus (~$1.50/tarea)
  = 350×$0.03 + 125×$0.15 + 25×$1.50 = $10.50 + $18.75 + $37.50 = ~$67

⚠️ Los precios varían según provider (DeepSeek vs Claude vs ChatGPT).
DeepSeek es 5-15× más barato que Claude para el mismo output. Lumba usa DeepSeek para volumen, Claude/Opus solo para criterio crítico.

📏 Reglas Clave del Sistema

1. Auditoría antes de entrega. Nada sale al cliente sin auditor. Sin excepciones.
2. Brief obsesivo. Sin objetivo, audiencia y criterios de éxito claros → NO se arranca.
3. Humano decide, agente prepara. Los agentes nunca aprueban entregables al cliente.
4. Devil's Advocate obligatorio. Antes de cerrar cualquier fase, el DA cuestiona TODO.
5. Memoria persistente. Cada cliente y proyecto tiene su memoria. Nunca se empieza de cero.
6. Modelos correctos. Flash para volumen (70%), Pro para arquitectura (25%), Opus para auditoría (5%).
7. Corte automático de costos. USD 10 por sesión → requiere aprobación. USD 50/día → alerta crítica.

🚀 Cómo Correr OpenClaw

Paso 1 — Prerrequisitos
  • Node.js ≥ 18 (recomendado 20+)  |  • npm ≥ 9
  • Una API key de DeepSeek (o Claude/GPT)
  • Windows / macOS / Linux

Paso 2 — Instalación
npm install -g openclaw

Paso 3 — Arrancar
openclaw gateway start
  → El gateway arranca en localhost:18789

Paso 4 — Estado
openclaw status  — verificá que esté running

Paso 5 — Agregar canales
  • Telegram: configurá el bot token y chat ID en la config
  • WhatsApp / Discord / Signal: mismo proceso

Paso 6 — Agregar skills
  • Las skills son plugins. Creálas en ~/.openclaw/skills/
  • Cada skill es una carpeta con SKILL.md + herramientas
  • Lumba Core = 25 agentes, cada uno apunta a sus skills

🔀 Flujo de Decisión Completo

1. Vos escribís un prompt en Telegram (o cualquier canal)
2. El Orchestrator lo recibe y clasifica:
    → Pregunta: responde directo, sin pipeline
    → Tarea de proyecto: arma plan de agentes
3. Si es proyecto, te dice: "Para 'X' necesito los agentes A, B, C. Costo est. $Y. ¿Arranco?"
4. Vos respondés SÍ → pipeline de 8 pasos se ejecuta
    → Investigación → Pensar → Cuestionar → Validar → Construir → Testear → Mejorar → Lanzar
5. Entre cada paso, el Devil's Advocate audita
6. Antes de entregar, validación humana obligatoria
7. Si en cualquier momento detecta algo riesgoso → te frena y pregunta

📋 Workflows Operativos

💻 1. Discovery + Definición Funcional

  • Research Agent investiga mercado y competencia
  • Business Strategist analiza viabilidad
  • Product Owner define roadmap y features
  • Analyst Functional escribe especificación
  • UX Designer crea wireframes y flujos
  • Scope Agent verifica alcance vs contrato
  • Devil's Advocate audita antes de avanzar

🎨 2. Diseño UX/UI Completo

  • UX Designer → arquitectura de información
  • Wireframes → prototipos interactivos
  • UI Designer → sistema de diseño + componentes
  • Estados: loading, empty, error, success
  • Responsive y accesibilidad WCAG AA
  • Brand Auditor verifica consistencia de marca

🏗️ 3. Desarrollo de Feature

  • Frontend/Backend/Data Architects diseñan
  • ADR Generator documenta decisiones técnicas
  • UI Designer implementa componentes
  • Code Reviewer revisa cada PR
  • Security Agent escanea vulnerabilidades
  • QA Engineer testea happy path + edge cases
  • Product Auditor audita antes de deploy

🐛 4. Bug Crítico en Producción

  • QA Engineer reproduce y documenta el bug
  • Backend/Frontend Architect diagnostica causa raíz
  • Fix + test de regresión
  • Code Reviewer aprueba hotfix
  • DevOps Engineer deploya con rollback plan
  • Post-mortem: ¿por qué no lo detectamos antes?

🔄 5. Soporte Evolutivo

  • Project Manager prioriza backlog mensual
  • Sprint de 2 semanas con Definition of Done
  • Code Reviewer mantiene deuda técnica visible
  • Research Agent actualiza análisis competitivo
  • Métricas de calidad monitoreadas

🎯 6. Auditoría Pre-Entrega

  • Product Auditor: specs vs implementación real
  • Security Agent: scan final de seguridad
  • QA Engineer: test de regresión completo
  • Devil's Advocate: checklist de 10 puntos
  • Client Translator: prepara comunicación al cliente
  • Validación humana obligatoria antes de enviar
