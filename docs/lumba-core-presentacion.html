03 — Flujo de Proyecto

Tres caminos, un sistema

No todo proyecto empieza desde cero. El sistema se adapta a lo que ya existe.

💡
Ejemplos Comunes:
• Un nuevo e-commerce headless con pasarela de pago para una marca de indumentaria.
• Un SaaS o CRM a medida para automatizar la gestión y analíticas de una empresa.
• Una aplicación móvil interactiva que requiere diseñar la base de datos, UX/UI e infraestructura desde cero.
W00 Project Assessment & Triaje flash
Jarvis clasifica como Tipo A (Greenfield), ejecuta el checklist de complejidad (6 preguntas) y consulta MATRIZ-SQUADS.md para convocar al squad. Crea /proyectos/{nombre}/ con state.json y MEMORIA-PROYECTO.md.
W01 Brief Obsesivo flash / pro
PM Agent construye el brief completo: objetivo, audiencia, restricciones, criterios de éxito, ejemplos y decisor final. Sin brief completo no se arranca.
📋 PM Agent
W02 Propuesta Comercial pro
Se genera la propuesta para el cliente con alcance, timeline y presupuesto. Requiere aprobación del cliente antes de continuar.
W03 Discovery & Definición Funcional pro
Business Strategist + Product Owner + Analyst Functional. Se cierran reglas de negocio ANTES de tocar la base de datos.
💼 Business Strategist 📋 Product Owner 📝 Analyst Functional
W04 Tech Stack Decision pro
Gero elige entre Stack A (Serverless), B (Containers) o C (K8s). Agentes validan la elección y generan ADR. El motor de DB queda confirmado antes de modelar.
🏗️ Frontend Architect ⚙️ Backend Architect 🚀 DevOps Engineer 😈 Devil's Advocate
W05 Diseño de Base de Datos opus
Data Architect diseña el modelo ER, migraciones SQL y ADRs sabiendo exactamente en qué motor corre. SOLO después de Discovery cerrado Y Tech Stack aprobado.
⚡ Data Architect (Opus) 😈 Devil's Advocate ⚙️ Backend Architect
W05.5 Bootstrap & Scaffolding flash
PM Agent crea la estructura de carpetas, configs (Prettier, ESLint, tsconfig), package.json y documentación base. Proyecto listo para codear en minutos.
W06–W07 Branding + UX/UI pro / opus
Brand Strategist + Identity Designer + UX/UI Designers. Identidad visual, flujos de usuario, wireframes y sistema de diseño.
🧠 Brand Strategist 🎨 UX Designer 🖌️ UI Designer
W08 Marketing pro
Estrategia de marketing, campañas, contenido y ads. Growth Gate y Paid Media Gate opcionales según el proyecto.
W09–W11 Build + QA + Deploy pro
Frontend + Backend Architects construyen. Code Reviewer + QA Engineer validan. DevOps deploya. Documentation Agent documenta en paralelo.
🏗️ Frontend Architect ⚙️ Backend Architect 🔍 Code Reviewer 🧪 QA Engineer 🚀 DevOps 📚 Documentation
W12 Post-Launch (Semana 1) flash
Monitoreo de métricas, hotfixes, retrospectiva y captura de aprendizajes reutilizables.
💡
Ejemplos Comunes:
• Una tienda online en producción que sufre de lentitud extrema o caídas y requiere auditoría de arquitectura.
• Un sistema heredado (legacy) escrito en Node.js al que se le quiere agregar un módulo de suscripciones.
• Una plataforma web que requiere un rediseño visual completo manteniendo intacta la lógica de base de datos actual.
W00 Project Assessment — Tipo B (Brownfield) flash
Jarvis clasifica como Tipo B, ejecuta el checklist de complejidad (6 preguntas) y consulta MATRIZ-SQUADS.md para convocar al squad. Crea /proyectos/{nombre}/ con state.json y MEMORIA-PROYECTO.md.
AUDIT System Auditor — Autopsia Técnica pro + thinking
Auditoría completa del codebase existente en 5 dimensiones: Código, Arquitectura, Base de Datos, Seguridad y DevOps. Score X/10 por dimensión. Hallazgos clasificados como Críticos, Mayores o Menores.
🔍 System Auditor 🔒 Security Agent
GAP Gap Analysis & Recomendación pro
¿Qué tiene? ¿Qué necesita? ¿Cuánto esfuerzo? Recomendación: Refactorizar, Extender o Reescribir (por componentes).
DECIDE Gero Decide el Camino
Con el audit report y el gap analysis, Gero elige si refactorizar el código existente o reescribir componentes desde cero. Los agentes nunca deciden esto solos.
EXEC Ejecutar Plan de Acción pro
Según la decisión: workflow de refactor/evolutivo o reescritura selectiva por componentes, pasando por los mismos Quality Gates que un proyecto nuevo.
💡
Ejemplos Comunes:
• Un proyecto donde el cliente ya entrega los diseños en Figma validados, pero no se ha escrito código.
• Un MVP a medio desarrollar por otro equipo que requiere auditoría de completitud y finalización de features.
• Una especificación funcional detallada (Specs) que necesita ser traducida a arquitectura de base de datos y desarrollo.

📋 PM Agent 🔬 Research Agent

¿Qué fases del pipeline ya se cumplieron? ¿Qué falta? Se genera un gap analysis específico.
FILL Gap Fill — Solo lo que Falta según fase
Se ejecutan SOLO las fases faltantes del pipeline estándar. No se rehace lo que ya funciona.

04 — Quality Gates

Nada sale sin auditoría

Cada fase tiene un Quality Gate. Si no pasa, no avanza. El Devil's Advocate puede bloquear entregas.

🎯
Auditoría Automática
Cada entregable pasa por un agente auditor especializado antes de llegar al humano.
✓ Brand Auditor revisa entregables de branding
✓ Marketing Auditor revisa campañas y copy
✓ Product Auditor revisa specs y UX/UI
✓ Code Reviewer revisa código pre-merge
😈
Devil's Advocate
Obligatorio en cierres. Cuestiona supuestos, busca contradicciones, identifica riesgos. Tiene poder de veto.
⚠️ Revisa supuestos no validados
⚠️ Identifica riesgos invisibles
⚠️ Evalúa alternativas descartadas
🔴 Override requiere aprobación del Founder
👤
Validación Humana
Jarvis notifica por Telegram. El humano aprueba, pide cambios o rechaza. Si no responde en 48h, se escala.
📱 Notificación con link al output
⏱️ Timeout de 48h para fase, 4h para deploy
🔁 Re-spawn del agente si hay cambios
📝 Registro JSON de cada aprobación
🔒
Capa Determinística
Antes de que un humano o agente revise código, la máquina ya limpió formato, tipado e imports.
✓ Prettier formatea automáticamente
✓ ESLint caza código muerto y anti-patterns
✓ tsconfig strict mata tipado débil
✓ Pre-commit hooks bloquean código sucio
05 — Principios Operativos

Las reglas que no se negocian

15 principios que gobiernan el comportamiento de todo agente.

P0
Auditoría antes de entrega
La métrica norte: % entregas sin corrección posterior.
P1
Humano decide, agente prepara
Los agentes investigan y sugieren. Nunca aprueban.
P2
Primero negocio, después técnica
Sin problema de negocio claro → no se arranca.
P3
Brief obsesivo
Objetivo, audiencia, restricciones, criterios de éxito.
P5
Criterio compartido
Skills, checklists y templates codifican el criterio senior.
P6
Memoria por cliente
Decisiones, rechazos, tono de marca → siempre disponibles.
P7
Trazabilidad total
Quién propuso, quién aprobó, cuándo, qué se descartó.
P11
Proceso de 8 pasos, inviolable
Investigar → Pensar → Pensar de nuevo → Validar → Construir → Testear → Mejorar → Lanzar.
P13
Validar antes de construir
¿Resuelve un dolor real? ¿Existe algo similar? ¿Costo < beneficio?
P14
Devil's Advocate obligatorio
Puede bloquear entregas. Override requiere aprobación del Founder.
