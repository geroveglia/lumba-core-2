⚙️ Infraestructura
Setup de la Mac Mini — se hace una sola vez
1. Preparar la Mac Mini
macOS actualizado, internet estable. No necesita monitor, teclado ni mouse después del setup inicial. Puede estar en un rincón conectada solo a corriente y ethernet/wifi.
2. Instalar Node.js + Git
Desde nodejs.org o con Homebrew: brew install node git
3. Instalar OpenClaw
npm install -g openclaw
4. Clonar Lumba Core
git clone <url-del-repo> ~/lumba-core
5. Configurar Telegram Bot
Crear bot con @BotFather → guardar token. Configurar ~/.openclaw/openclaw.json.
6. Arrancar el Gateway
openclaw gateway start — queda corriendo para siempre. Se puede configurar como servicio del sistema para que arranque solo al prender la Mac.
7. Crear workspaces por proyecto
Para cada proyecto: copiar lumba-core → ~/proyectos/<nombre> → git init → configurar remote de GitHub.

🤖 Los Agentes
Quiénes son, cómo se organizan, cómo trabajan

Lumba Core tiene 25 agentes especializados organizados en 3 redes + agentes universales. Cada uno tiene skills específicas (metodologías, checklists, templates) que usa para trabajar.

🚨
Los agentes nunca aprueban entregables al cliente. Preparan, auditan, documentan. Pero siempre hay una validación humana antes de que algo salga. El criterio final es humano.

🧠 Modelos por tipo de tarea

Arquitectura, debugging, análisis, estrategiaPro25%"Diseñá el modelo de datos multi-tenant"
Auditoría, seguridad, Devil's AdvocateGPT-5.55%"Auditá el código antes del merge"

🔄 El Pipeline de 8 Pasos
De tu prompt a la entrega final — inviolable

Cada tarea de proyecto sigue este proceso. No se saltean pasos. Si alguien (humano o agente) intenta saltear, el sistema bloquea.

Detalle de cada paso

🏗️ PASO 1 — INVESTIGAR Research Agent analiza mercado, competencia, contexto. Business Strategist evalúa viabilidad. → Output: documento de investigación con fuentes. 🧠 PASO 2 — PENSAR Product Owner define roadmap, features, backlog. Analyst Functional escribe especificación. UX Designer crea wireframes y flujos. → Output: especificación funcional + roadmap. 😈 PASO 3 — CUESTIONAR Devil's Advocate revisa TODO. Scope Agent verifica alcance vs contrato. → Output: reporte de riesgos + ajustes al plan. ✅ PASO 4 — VALIDAR Client Translator prepara comunicación para el cliente. → ACÁ EL HUMANO REVISA Y APRUEBA. Sin aprobación explícita, no se avanza. 🏗️ PASO 5 — CONSTRUIR Frontend + Backend + Data Architects desarrollan. UI Designer implementa componentes. ADR Generator documenta decisiones técnicas. → Output: código funcional. 🧪 PASO 6 — TESTEAR QA Engineer ejecuta plan de testing. Code Reviewer audita cada PR. Security Agent escanea vulnerabilidades. → Output: reporte de bugs + fix. 🔧 PASO 7 — MEJORAR Refactor, ajustes, deuda técnica. Code Reviewer verifica métricas de calidad. → Output: código limpio listo para producción. 🚀 PASO 8 — LANZAR DevOps Engineer prepara deploy + rollback plan. Product Auditor audita specs vs implementación real. → Validación humana final. Se hace deploy.
🔒
Entre los pasos 4 y 8 siempre hay intervención humana. Los agentes trabajan autónomamente en los pasos 1-3 y 5-7, pero el OK para seguir es humano.

👥 Cómo Interactúa el Equipo
El día a día trabajando con Lumba Core

📱 Flujo típico de un día

Gero abre Telegram
En su PC, su celular, donde sea. No necesita abrir nada más.
Escribe un prompt
"Necesito el sistema de autenticación para Looped. JWT con refresh tokens, roles admin/user, y endpoints de registro/login/logout."
Orchestrator clasifica
Determina que es una tarea de Core-Product, complejidad media. Arma el squad: Backend Architect + Data Architect + Code Reviewer + Security Agent.
Orchestrator te responde
"Gero, para esto necesito 4 agentes. Pipeline estimado: 4 pasos (construir→testear→mejorar→lanzar). Costo ~$3-5 USD. ¿Arranco?"
Vos decís "Sí"
Los agentes trabajan. Vas recibiendo updates en Telegram: "Ya hice el modelo de datos" → "Endpoints listos" → "Code review aprobado"
Código en GitHub
"Listo Gero. Commit abc123. PR #12 en github.com/lumba/looped. 8 archivos, 340 líneas. Revisá cuando puedas."
Revisás desde tu PC
Abrís GitHub, ves el diff, dejás comentarios. Si está bien → merge. Si no → le pedís cambios por Telegram.

🔐 3 niveles de seguridad

ModoCómo funcionaCuándo usarlo
🟢 AutomáticoAgente codea → commitea → pushea → te avisa. Revisás después.Prototipos, features no críticas, confianza alta
🟡 Con PR (recomendado)Agente codea → crea branch → pushea → abre PR. Vos mergeás.Día a día. Todo se revisa antes de mergear.

📋 Resumen Operativo
Tabla rápida de consulta
PreguntaRespuesta
¿Dónde corre?En una Mac Mini dedicada, siempre prendida, conectada a internet
¿Cómo me conecto?Desde Telegram, en tu PC o celular. Nada más.
¿Necesito instalar algo en mi PC?No. Solo Telegram.
¿Cuántas personas pueden usar?Ilimitado. Cada chat de Telegram es una sesión independiente.
¿Pueden trabajar varios al mismo tiempo?Sí. El gateway procesa hasta 4 tareas en paralelo (configurable).
¿Se mezclan los proyectos?No. Cada proyecto tiene su workspace aislado.
¿Los agentes deciden solos?No. Preparan, auditan, documentan. Las decisiones finales son humanas.
¿Qué pasa si quiero customizar algo para mi proyecto?Editás los archivos de tu workspace sin afectar a los demás.
¿Cómo veo el código que genera?El agente lo commitea a GitHub. Lo revisás desde tu PC como cualquier PR.
¿Los datos de los clientes están seguros?Sí. Datos sensibles no pasan por agentes. NDA se respeta. Workspaces privados.
¿Cuánto cuesta?~$2-5 USD por proyecto simple. ~$10-25 mediano. ~$30-80 complejo. + API keys.
¿Qué pasa si se corta internet?Los agentes no responden hasta que vuelva. El código ya commiteado está a salvo en GitHub.
⚡
Lumba Core no reemplaza al equipo. Lo potencia. Cada persona sigue siendo dueña de sus decisiones. Los agentes son herramientas de criterio, no reemplazos. El objetivo no es hacer más rápido — es hacer mejor, con menos corrección posterior.
