# PROCESO DE 8 PASOS — LUMBA CORE

> **Versión:** v1.0
> **Tono:** Manual operativo.
> **Propósito:** definir el proceso inviolable que aplica a TODO trabajo en Lumba.
> **Última actualización:** 23 de mayo de 2026.

---

## 1. PROPÓSITO

Este es el método de trabajo de Lumba. **Aplica a todo proyecto sin excepción.**

No es una guía. No es una recomendación. **Es ley operativa.**

Nadie en Lumba (humano o agente) puede saltarse un paso.

---

## 2. LOS 8 PASOS

```
1. INVESTIGAMOS     → contexto, mercado, usuarios, restricciones
2. PENSAMOS         → estructura, modelo conceptual, decisiones core
3. PENSAMOS DE NUEVO → cuestionar lo pensado, detectar agujeros, refinar
4. VALIDAMOS        → contra usuarios, realidad, antiproducto
5. CONSTRUIMOS      → código, recién acá se hace
6. TESTEAMOS        → funcionalidad real, no asunciones
7. MEJORAMOS        → refactor, performance, deuda técnica
8. LANZAMOS         → al mundo
```

---

## 3. POR QUÉ EXISTE ESTE PROCESO

### El problema

La mayoría de las agencias salta a producir sin pensar. Resultado: entregas con errores, correcciones constantes, equipo quemado.

### La solución de Lumba

Invertir más tiempo arriba (pasos 1-4) para ahorrar el triple abajo (pasos 5-8).

### El insight clave

> **Construir sin validar es la receta para la corrección posterior.**

Y la corrección posterior es el dolor #1 de Lumba que Lumba Core resuelve.

---

## 4. EXPLICACIÓN PASO A PASO

### Paso 1 — Investigamos

**Qué hacemos:**
- Entender contexto del cliente.
- Investigar mercado y competencia.
- Conocer usuarios y sus dolores.
- Identificar restricciones (presupuesto, técnicas, legales, de marca).
- Recopilar información existente.

**Entregable:**
- Documento de discovery / diagnóstico inicial.

**Quién opera:**
- Research Agent + agentes especialistas según área.

**No avanzamos hasta:**
- Tener información suficiente para fundamentar decisiones.

---

### Paso 2 — Pensamos

**Qué hacemos:**
- ⚡ **En proyectos digitales: diseñar el modelo de datos PRIMERO** (ver Workflow 0).
- Armar estructura del problema.
- Proponer modelo conceptual o estratégico.
- Definir decisiones core.
- Estructurar opciones.

**Entregable:**
- Documento de estructura / hipótesis / modelo.
- **En proyectos digitales: modelo de datos completo (obligatorio antes de seguir).**

**Quién opera:**
- Vertical Leads (brand-strategist, marketing-strategist, business-strategist).
- **data-architect (Opus)** — primer agente técnico en proyectos digitales.

**No avanzamos hasta:**
- Tener una propuesta clara de cómo abordamos el problema.
- **En proyectos digitales: modelo de datos diseñado y aprobado.**

---

### Paso 3 — Pensamos de nuevo

**Qué hacemos:**
- Cuestionar lo que pensamos en el Paso 2.
- Detectar agujeros lógicos.
- Identificar supuestos no validados.
- Buscar alternativas que descartamos sin motivo.
- Devil's Advocate activo.

**Entregable:**
- Reporte de challenge con riesgos detectados.

**Quién opera:**
- Devil's Advocate (obligatorio).
- Equipo humano cuestionando con criterio.

**No avanzamos hasta:**
- Resolver o aceptar conscientemente los riesgos detectados.

**Anti-pattern:**
- Saltarse este paso porque "ya pensamos en el 2".

---

### Paso 4 — Validamos

**Qué hacemos:**
- Confrontar el modelo con usuarios reales.
- Validar contra realidad operativa.
- Confirmar que respeta el antiproducto.
- Probar con prototipos / wireframes / pilotos.

**Entregable:**
- Modelo validado o ajustado.

**Quién opera:**
- Equipo + cliente (cuando aplica).

**No avanzamos hasta:**
- Tener evidencia de que el modelo funciona.

**Anti-pattern:**
- Confundir validación con "le pregunté a mi socio".

---

### Paso 5 — Construimos

**Qué hacemos:**
- **Recién acá hacemos.**
- Código, diseño, copy, campaña, presentación, etc.

**Entregable:**
- El producto / pieza / contenido / sistema.

**Quién opera:**
- Agentes especialistas + equipo humano.

**No avanzamos hasta:**
- El entregable cumple los criterios definidos en Paso 2.

**Anti-pattern:**
- Empezar acá sin completar los pasos 1-4.

---

### Paso 6 — Testeamos

**Qué hacemos:**
- Probar funcionalidad real.
- QA contra criterios de aceptación.
- Detectar bugs, errores, fricciones.
- No asumir que "anda porque lo probé yo".

**Entregable:**
- Reporte de QA con hallazgos.

**Quién opera:**
- QA Engineer + equipo.

**No avanzamos hasta:**
- Todos los bugs críticos resueltos.

**Anti-pattern:**
- "Para mí está bien" sin testing estructurado.

---

### Paso 7 — Mejoramos

**Qué hacemos:**
- Refactor de código.
- Ajustes de performance.
- Eliminación de deuda técnica.
- Pulido final.

**Entregable:**
- Versión final pulida.

**Quién opera:**
- Code Reviewer + especialistas.

**No avanzamos hasta:**
- El nivel de calidad supera el mínimo aceptable.

---

### Paso 8 — Lanzamos

**Qué hacemos:**
- Entrega al cliente.
- Deploy a producción.
- Publicación al mundo.
- Activación de campaña.

**Entregable:**
- El entregable en manos del cliente / usuario.

**Quién opera:**
- Humano (siempre con validación final).

**No terminamos hasta:**
- Confirmar que llegó correctamente y se monitorea el resultado.

---

## 5. MAPEO CON LA FÓRMULA LUMBA

El proceso se complementa con la fórmula:

```
Entender → Definir → Diseñar → Construir → Medir → Evolucionar
```

| Fórmula Lumba | Pasos del proceso |
|---|---|
| Entender | 1. Investigamos |
| Definir | 2-3. Pensamos / Pensamos de nuevo |
| Diseñar | 4. Validamos (con prototipos / wireframes) |
| Construir | 5. Construimos |
| Medir | 6. Testeamos |
| Evolucionar | 7-8. Mejoramos / Lanzamos |

---

## 6. APLICACIÓN POR EQUIPO

### En Core-Brand

```
Investigamos  → discovery + benchmark
Pensamos      → posicionamiento + territorios
De nuevo      → challenge de estrategia
Validamos     → con workshops + moodboards
Construimos   → identidad visual + manual
Testeamos     → aplicaciones reales
Mejoramos     → ajustes finales
Lanzamos      → entrega completa
```

### En Core-Marketing

```
Investigamos  → diagnóstico de canales + competencia
Pensamos      → estrategia + plan + hipótesis
De nuevo      → challenge de hipótesis
Validamos     → con tests pequeños (creativos, audiencias)
Construimos   → campañas + contenido + copys
Testeamos     → QA pre-lanzamiento
Mejoramos     → optimización pre-launch
Lanzamos      → publicación
```

### En Core-Product

```
Investigamos  → discovery + relevamiento + entidades de negocio
Pensamos      → ⚡ PRIMERO: diseño de base de datos (Workflow 0)
                → DESPUÉS: definición funcional + UX + arquitectura
De nuevo      → challenge de alcance + decisiones técnicas
Validamos     → con prototipos + cliente
Construimos   → desarrollo
Testeamos     → QA + tests automáticos
Mejoramos     → refactor + optimización
Lanzamos      → deploy a producción
```

**Regla fundacional de Core-Product:**
> El modelo de datos se diseña ANTES que cualquier definición funcional, pantalla, API o línea de código. Es el cimiento del sistema. Se diseña con Opus. Ver `equipos/core-product/workflows/00-diseno-base-datos.md`.

## 7. CADA PASO TIENE GATE

Antes de avanzar al siguiente paso, **gate obligatorio**:

```
Paso completado → Gate de validación → ¿Pasa? → Avanza
                                    ↓
                                  ¿No pasa? → Vuelve a iterar
```

Ver `QUALITY-GATES.md` para detalles de cada gate.

---

## 8. CONTROL OPERATIVO

Cada agente que opera en Lumba Core debe responder a esta pregunta antes de actuar:

> **¿En qué paso estamos? ¿Cuál es el entregable de este paso?**

Si no se puede responder con claridad:

- El trabajo se detiene.
- Se consulta al PM o Founder.
- Se aclara antes de seguir.

---

## 9. NO HAY ATAJOS

### Razones que NO justifican saltarse pasos

- "El cliente lo necesita para ayer."
- "Ya lo hicimos antes parecido."
- "Es algo chico, no requiere tanto proceso."
- "Confío en mi intuición."

### Razones que SÍ justifican una excepción

- **Emergencia genuina** con impacto al cliente. En ese caso:
  - Se registra el bypass.
  - Se hace post-mortem después.
  - Se ajusta para que no vuelva a pasar.

**Bypass máximo permitido:** 5% de los proyectos.
